# 教室管线评审 · 2026-09-29

建议以一个教室主工程作为日常编辑入口：同一教室的镜头共享本地模型、材质与贴图，不再让每次材质微调经过制作源、复制发布库和镜头重载。重复件继续共享网格与集合实例。不同场景/模拟和高模制作仍可独立保存。

**状态更新（2026-09-29）：用户已要求继续并完成当前镜头正式迁移。** 本文以下内容保留为迁移前的问题与性能评审快照；发布结果、使用方式和恢复副本见[迁移记录](../classroom_pipeline_migration_20260929/report.md)。后续第二镜头尚未正式创建。

## 查到的问题

1. 当前主镜头直接引用建筑源 `classroom_environment.blend` 和道具库 `classroom_assets.blend`。
2. `classroom_props.blend` 与 `classroom_assets.blend` 均无外部库依赖：黑板是独立副本，不是自动同步的嵌套Link。当前两份同名黑板材质分别19/16个节点，已出现差异；不能用旧制作源覆盖镜头正在使用的材质。
3. 当前道具库55个集合中52个未挂入任何Scene，虽能被外部链接，打开库时却不易找到。此前黑板缺席Outliner正是这一问题。
4. 未找到保留中的通用发布入口；历史一次性发布脚本已在9/27清理。现有规范要求“经发布库”却没有对应的日常编辑流程。
5. 主镜头只列出268个场景对象，但引用数据已进入内存：14897个对象、10766个网格、247种材质和402个图像数据块。这里包含非渲染/旧数据，不能把这些总数直接当成渲染可见数；也不能把268当作模型负担。

## 性能：拆文件与实例复用必须分开

把同一批数据放进一个文件，不等于逐桌复制网格。实验采用当前未保存镜头的副本，通过Make Local保留全部集合实例和网格共享；不执行Make Instances Real。

- 本地化前后对象、网格、材质、图像、顶点、面数、实例分布和网格共享分布完全相同：2116124个原始顶点、2050024个原始面。**拆文件没有减少这批几何数据。**这些不是修改器后渲染三角面数。
- 实例仍为25张桌、24把椅、167个罐体等，未变为逐实例独占网格。
- 所有链接对象/材质在实验候选中变为本地，黑板材质及节点树可编辑。
- 链接镜头自身约4.95 MiB；本地副本约65.92 MiB。链接镜头仍依赖外部道具库61.47 MiB和建筑源6.61 MiB，外置贴图两者均要读取。小主文件不是小内存的证据。文件大小会受压缩和孤立数据清理影响。
- 渲染实验使用同一1076帧、640×270、16 samples、OptiX、固定seed、不去噪；计时包含Cycles同步与渲染调用。结果见实测记录。两组有限A/B不能当成稳定速度百分比，更不能代表完整动画FPS或GPU显存；用户主Blender同时打开，系统资源有干扰。

证据：[本地化前后数据](localization.json)、[链接版小样](linked_test.png)、[本地版小样](local_test.png)。实测摘要在 `measurements.json`。本地化候选仅用于结构对照，还不是完成资产选择入口与多镜头隔离的正式迁移版本。

两张首轮小样的8位解码平均绝对像素差约0.000525/255，并非逐像素相同；少量随机亮点有差异。镜头中原有测试人物缺少Houdini `opdef:` 贴图，两种版本都有相同警告和粉色部位，本次未把既有问题作为资产管线迁移的改动对象，也不将这些小样标为成片。

## 推荐的日常使用方式

1. **打开一个教室主工程。** 先沿用当前固定镜头路径，迁移时将它确认为教室日常编辑入口；不靠改名解决结构问题。未来其它地点各自一个主工程，不把整部短片塞进一个文件。
2. **同一教室每个镜头用独立Scene。** 共用环境/道具集合及默认材质；相机、灯光、World、动画控制器/Action、帧段和合成设置按镜头独立。不能简单Linked Copy整个Scene，否则相机、World和动画也可能共用。
3. **在镜头灯光下改材质。** 黑板等频繁编辑的单件应能在当前镜头直接选择；必要时只展开这一份实例，保持网格与材质共享。桌椅/罐体等重复件保留实例，提供清晰的模板/材质入口，可将材质编辑器固定到目标材质后继续看最终相机。仅把链接转为本地仍不解决实例内部不可直接点选的问题，这一步须单独验收。
4. **默认改动影响教室所有镜头。** 用户在sh010将共用黑板粗糙度改动，sh020等引用同一材质，立即使用新值。
5. **少量镜头例外显式创建。** 只给需要例外的对象/集合建立镜头专属实例或对象副本，几何尽量仍共享；对象材质槽指向独立材质。共用对象的材质槽不能直接改，否则仍会影响其它Scene。例外材质要标记归属和为何分叉。
6. **高模、烘焙、布料模拟源保持独立。** 它们用于制作和重算，确认结果后导入主工程。它们不是当前镜头外观的第二个编辑权威源；日常调色/粗糙度不回到旧props文件。

## 代价与边界

- 主工程变大、保存写入量增加；同一地点多个镜头集中在一个文件，不适合多人同时写入。这是当前个人制作、快速试镜头的可接受取舍，需由用户确认。
- 本地化之后不再自动接收旧资产源的更新。后续确实需要从高模/资产制作源导入更新时，应明确导入哪些网格，并保护主工程的材质、UV匹配与动画。
- 多Scene可以隔离镜头设置，但共享对象的动画/可见性/材质仍可能互相影响，必须按上述归属划分。若以后协作规模或单文件实测负担增加，再评估资产Link加局部Override；不把复杂Override作为当前默认入口。
- 当前还有52个不可发现集合、许多小零件和高模桌椅实例值得做性能调查，但本轮不把它们宣判为瓶颈，也不擅自删减美术结果。

## 若采用，迁移验收应是什么

从实时镜头备份及其实际使用的两个库取数据，保留已分叉的旧源作历史恢复，不执行旧生成/发布脚本。先得到可审阅候选，完成：

- 当前主机位前后对照；几何、实例数量/位置、相机/Sky动画、World、色彩管理、贴图路径一致。
- 黑板在镜头光照下可以直接打开节点、改粗糙度并立即看到效果；改回后画面恢复。
- 新建第二个测试Scene：共用材质会联动；镜头专属材质、相机、World与Action不会串改。
- 重开、路径检查、保存体积和性能对照通过，再替换正式入口并更新规范。旧props/library不再作为并行的日常修改入口；是否归档单独按迁移清单执行，不直接删除。

## 原理依据与事实来源

- [Blender：Link与Append](https://docs.blender.org/manual/en/5.2/files/linked_libraries/link_append.html)：Link保留外部引用，源变化在重新加载时读入；Append成为独立数据。5.1实际行为另由本机实验核实。
- [Blender 5.1：Scene共享数据与多镜头用途](https://docs.blender.org/manual/id/5.1/scene_layout/scene/introduction.html)：一个文件可以有多个Scene并共享对象/材质/集合；Linked Copy会共享更多数据，不能当作自动隔离。
- [Blender：Library Overrides](https://docs.blender.org/manual/en/5.1/files/linked_libraries/library_overrides.html)：保留外部依赖并局部改写的备选方式，会引入重同步管理。
- 当前源审计：`07_pipeline/cache/pipeline_review_20260929/source_audit_readonly.json`。审计没有把材质节点差异认定为损坏，保留用户修改。
